## 1. Project Goal

Transform `laptopfinder` into a reproducible **Laptop Intelligence Platform**. The pipeline ingests raw laptop data from CSV, JSONL, and Markdown sources; normalises it into a canonical SQLite database; scores candidates against a defined rubric; and exports ranked shortlists. **Obsidian (under Git) is the knowledge layer. SQLite is the data layer. Python is execution. Git is the single canonical source of truth for both.**

### End state

- Fresh checkout → `lf init` → database ready
- All datasets import cleanly and idempotently
- `lf search <term>` returns ranked candidates with price, retailer, and recommendation
- `lf export excel` and `lf export markdown` regenerate the current shortlist from SQLite
- All tests pass

## 3. Architecture

```
Raw Sources  (CSV · JSONL · Obsidian MD · saved pages)
     ↓
  Import     — parse and validate; emit structured records
     ↓
 Normalize   — deduplicate, canonicalise names, merge aliases
     ↓
 Canonical   — SQLite (laptop_intelligence.db)
  Database
     ↓
  Scoring    — configurable rubric; versioned; never overwrites history
     ↓
  Search     — CLI full-text + filter over canonical products
     ↓
  Export     — Excel shortlist · Markdown report · Obsidian note stubs
```

### Obsidian ↔ Git integration

```
laptopfinder/               ← Git repo (source of truth)
├── docs/                   ← architecture, decisions, this file

│   ├── laptops/            ← one note per canonical product
```

**Knowledge** (prompts, decisions, research) → lives in `vault/` as Markdown, committed to Git.

## 5. Database Schema

All tables use integer PKs and FK constraints. SQLite WAL mode enabled.

| Table | Purpose |
|---|---|
| `products` | One row per canonical hardware configuration |
| `cpu` | Normalised CPU catalogue (model, cores, TDP) |
| `gpu` | Normalised GPU catalogue (model, VRAM, arch) |
| `display` | Display specs (size, resolution, panel type) |
| `retailers` | Canonical retailer names + marketplace type |
| `listings` | Active market listings linked to a product |
| `price_history` | Timestamped price observations per listing; append-only |
| `evaluations` | LLM-generated evaluation records with source provenance |
| `evidence` | Raw excerpts linked to products with confidence + timestamp |
| `score_versions` | Versioned score snapshots; never updated in place |

> Do not add columns speculatively. Add columns when a milestone explicitly requires them.

## 6. CLI Commands

Entry point: `lf` (or `python -m laptopfinder.intelligence.cli`)

```bash
# Initialise database
lf init

# Import datasets
lf import unified data/unified_llm_canonical_2026-05-18.csv
lf import evidence data/chatgpt_export_harvest_evidence.jsonl
lf import prices data/lf-price-baseline.csv
lf import prices data/watchlist_scored_active.jsonl

# Search
lf search "RTX 5090"
lf search "legion" --min-vram 16 --max-price 3000

# Score all unscored products
lf score

# Export
lf export excel output/shortlist.xlsx
lf export markdown output/shortlist.md

# Obsidian note generation (M9)
lf export obsidian vault/laptops/
```

All commands are **idempotent and rerunnable**.

## 7. Import Contracts

### unified importer (`import unified`)
- **Input:** `unified_llm_canonical_2026-05-18.csv`
- **Output:** rows in `products`, `cpu`, `gpu`, `display`, `evidence`
- **Idempotency:** match on `(brand, model, cpu_id, gpu_id)`; skip if exists, update evidence count
- **Duplicates:** merge into canonical product; log alias
- **Logging:** INFO per product inserted; WARN per skipped row with reason
- **Failures:** skip malformed rows; log ERROR with row number; continue

### evidence importer (`import evidence`)
- **Input:** JSONL with `product_ref`, `excerpt`, `confidence`, `source`, `timestamp`
- **Output:** rows in `evidence` linked to `products`
- **Idempotency:** deduplicate on `(product_id, sha256(excerpt))`
- **Duplicates:** skip silently; increment dedup counter
- **Logging:** INFO summary at end
- **Failures:** skip unparseable lines; log ERROR; continue

### prices importer (`import prices`)
- **Input:** CSV or JSONL with price, retailer, listing URL, observed_at
- **Output:** rows in `retailers`, `listings`, `price_history`
- **Idempotency:** `price_history` is append-only; listings upserted on URL
- **Duplicates:** same URL + same price + same day → skip
- **Logging:** WARN if product_ref unresolved
- **Failures:** skip; log; continue

## 8. Normalization Rules

- **One canonical product per hardware configuration** — unique on `(brand, model_slug, cpu_id, gpu_id, ram_gb, storage_gb)`
- **Merge aliases** — "Legion 7i Gen 9" and "Lenovo Legion 7i (Gen 9)" → same canonical product; store alias in `products.aliases` JSON column
- **Normalize retailers** — "ebay.com.au", "eBay AU", "eBay" → `ebay_au`; map in `config/retailer_aliases.yml`
- **Normalize CPUs/GPUs** — canonical name from lookup table; raw value preserved in source column
- **Preserve provenance** — every imported row records `source_file`, `import_run_id`, `imported_at`
- **Never overwrite historical observations** — `price_history` and `evaluations` are append-only
- **Preserve raw values** — store original string alongside normalised FK

## 9. Coding Conventions

- **Python 3.12+** with type hints everywhere practical
- **Small, focused modules** — one responsibility per file
- **Minimal dependencies** — stdlib + `sqlite3`, `typer`, `openpyxl`, `pydantic` (optional); no ORM
- **Dataclasses or Pydantic** only where schema validation is genuinely needed
- **pytest** for all tests; fixtures in `conftest.py`
- **Black** for formatting; **Ruff** for linting
- **Deterministic behavior** — no random seeds, no time-dependent defaults without injection
- **Structured logging** — `structlog` or stdlib `logging` with JSON formatter
- **Avoid global state** — pass `db_path` and `config` explicitly
